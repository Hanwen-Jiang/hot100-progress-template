# Hot 100 进度仓

这是力扣「[热题 100](https://leetcode.cn/studyplan/top-100-liked/)」的**个人进度仓库**：记录你每道题的状态，存放你自己写的题解，以及每一次值得记的尝试（包括没通过的）。

题目、分层提示、动画演示和标准题解在网站 **https://leetcode.cgent.link** 上。用 GitHub 登录网站后，它会读取你账号下的 `hot100-progress` 仓库，显示你自己的进度和题解；在网站上改的状态也会直接提交到这个仓库。

## 怎么开始

1. 点右上角的 **Use this template → Create a new repository**，仓库名填 `hot100-progress`（名字要一致，网站按这个名字找），选 **Public**。
2. 打开网站，用 GitHub 登录，按提示把网站的 GitHub App 装到这个仓库上。安装时选 **Only select repositories**，只勾 `hot100-progress`——网站只拿到这一个仓库的读写权限，碰不到你的其他仓库。

网站首页登录后会一步一步提示这两件事。

## 文件规则

网站和自动检查都按下面的规则读文件，不符合规则的文件读不到。每次 push 后，GitHub Actions 里的 `check` 会检查一遍。

### 1. 进度：`progress.json`

```json
{
  "version": 1,
  "problems": {
    "1": { "status": "已通过", "updatedAt": "2026-11-14" },
    "146": { "status": "曾通过", "updatedAt": "2026-10-02" }
  }
}
```

- 键是题号（字符串），值里的 `status` 只能是下面四种之一：
  - `已通过`：通过了，现在也会做
  - `曾通过`：通过过，但需要复习
  - `尝试过`：做过、提交过，但还没通过
  - `未开始`
- 没出现在 `problems` 里的题都算 `未开始`。刚创建的仓库是空的，也就是 0 进度。
- `updatedAt` 可选，格式 `YYYY-MM-DD`。

### 2. 题解：`solutions/<语言>/<四位题号>.<题名>[.<写法>].<后缀>`

| 语言目录 | 后缀 |
| --- | --- |
| `python` | `.py` |
| `java` | `.java` |
| `go` | `.go` |
| `cpp` | `.cpp` |
| `c` | `.c` |
| `javascript` | `.js` |
| `typescript` | `.ts` |
| `rust` | `.rs` |
| `kotlin` | `.kt` |
| `swift` | `.swift` |
| `csharp` | `.cs` |

- 题号补齐到四位，题名照抄 `hot100.json` 里的 `name`，例如 `solutions/python/0001.两数之和.py`、`solutions/java/0146.LRU 缓存.java`。
- 同一道题的多种写法，在题名后面加一段写法名：`solutions/python/0200.岛屿数量.BFS.py`。
- 用力扣插件生成的 Java 文件，网站只显示 `submit region` 标记之间的代码，本地测试代码不会出现在页面上。
- 不在热题 100 里的题也可以放进来，网站暂时不显示，但不会报错。

### 3. 尝试记录：`attempts/<四位题号>.<题名>/<YYYY-MM-DD>.<序号>.<结果>.md`

每一次值得记的尝试一个文件，通过的、失败的都记。`solutions/` 放整理好的最终写法，`attempts/` 按时间放每一次**原样**提交的代码和当时的分析。

- 目录名和题解一样：四位题号 + `hot100.json` 里的题名，例如 `attempts/0200.岛屿数量/`。
- 文件名：日期 + 当天第几次（从 1 开始）+ 结果，例如 `2026-11-13.1.思路不成立.md`、`2026-11-13.2.运行出错.md`。按「日期、序号」排序就是先后顺序。
- 结果只能是五种之一：`通过`、`答案错误`、`超时`、`运行出错`、`思路不成立`（还没写代码就被反例推翻）。
- 尝试记录不进 `progress.json`，网站直接从文件里读；题目状态还是在 `progress.json` 里改（没通过时记 `尝试过`）。

文件内容是固定格式：

````markdown
---
lang: python
---

## 错在哪里

一两句话：错误本身，以及根本原因。

## 怎么发现的

哪个用例、哪条报错、哪个反例。

## 差在哪一步

和正确做法比，具体差在哪一步。

## 代码

```python
（当时提交的原样代码，不要改好再存）
```
````

- 开头的 `---` 之间是设置：`lang` 必填，取值是上面题解表里的语言目录名；`verbatim: false` 可选，表示代码**不是**原样提交（比如原样的没留下来，后来补写的），网站上会标出来。
- 正文用 `## ` 开头的小节。`错在哪里`、`怎么发现的`、`差在哪一步` 三节必须有；结果是 `通过` 时可以写成别的标题（比如 `## 说明`），只要有一节就行。还可以加别的小节（比如 `## 后续`），网站会照样显示。
- `## 代码` 一节放一个代码块；结果是 `思路不成立` 时可以没有，其他结果必须有。
- 小节里写纯文本即可，网站按原样显示，不渲染 Markdown。

`hot100.json` 是 100 道题的清单（题号、题名、难度、专题、重要程度、建议的文件名），新建文件时照着它取名最省事。

## 不要做的事

- 不要改 `progress.json` 的整体结构，也不要删掉 `version` 字段。
- 不要把账号、密码、令牌之类的东西提交进来——这是公开仓库。
